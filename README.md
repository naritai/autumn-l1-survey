# Осенние силуэты: L1-опрос

Готовый локальный прототип для исследования понятности CAPTCHA. Шесть заданий, шесть вариантов ответа в каждом. Участник сразу попадает на первое задание, которое входит в результаты: вступления, тренировки и подсказок нет. Библиотека из 24 фигур, по два ролика на фигуру; фигуры внутри одного прохождения не повторяются. Результаты записываются в SQLite сразу после каждого ответа, затем отдельно сохраняется оценка понятности. На последнем экране — оценка инструкции, комфорта и необязательный комментарий.

Сессия создаётся автоматически при открытии страницы. Перезагрузка продолжает текущее прохождение и не создаёт нового участника, если cookie сохранилась. Движение запускается кнопкой «Показать движение»; время ответа отсчитывается с первого показанного кадра.

## Сначала проверить локально

На Mac можно дважды нажать `Запустить локально.command`. Откроется терминал с сервером; `Ctrl+C` остановит его. Для ручного запуска:

```sh
npm run preview
```

Откройте [опрос](http://127.0.0.1:8785/) и [результаты](http://127.0.0.1:8786/). Пробные ответы записываются отдельно в `data-pilot/survey.sqlite`. Сервер работает до `Ctrl+C` в этом терминале. Публиковать ссылку или устанавливать туннель для локальной проверки не требуется.

## Запуск на вашем Mac с ручной остановкой

Нужен **Node.js 24 или новее**. npm-пакеты устанавливать не нужно: сервер использует стандартные библиотеки Node.js, включая SQLite. Все 49 MP4 уже входят в проект: 48 роликов для заданий и один прежний тренировочный ролик, который не показывается в опросе.

В терминале, находясь в этой папке:

```sh
npm run tunnel:install
npm run survey:share
```

Первая команда скачивает официальный `cloudflared` из релиза Cloudflare на GitHub, сверяет SHA-256 и сохраняет его только в `.bin/` внутри проекта. Если GitHub ограничил загрузку или в релизе нет контрольной суммы, установите `brew install cloudflared`. Уже установленный системный `cloudflared` тоже подходит.

Вторая команда запускает сервер и бесплатный Cloudflare Quick Tunnel без аккаунта. Отправьте участникам напечатанную HTTPS-ссылку `https://….trycloudflare.com`. Туннель пропускает только порт опроса; результаты работают на другом локальном порту.

- `http://127.0.0.1:8785` — локальный опрос.
- `http://127.0.0.1:8786` — результаты и скачивание CSV, только на вашем компьютере.
- **Автоматического выключения нет.** Сервер и туннель работают, пока вы их не остановите.
- `Ctrl+C`, закрытие терминала или завершение процесса отключают доступ. База остаётся на диске.
- Mac должен оставаться включённым и подключённым к сети. Скрипт использует `caffeinate` против обычного сна; **не закрывайте крышку**.
- У Quick Tunnel нет гарантии доступности, а лимит — 200 одновременно выполняемых запросов, не 200 участников. Ссылка меняется при следующем запуске. При сетевых проблемах браузер показывает повтор сохранения.

Источник: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## Проверка до рассылки

```sh
DATA_DIR=./data-pilot npm start
```

Пройдите несколько заданий локально. В конце остановите сервер `Ctrl+C`. Пилотная база отделена от основной `data/survey.sqlite`; не используйте основную базу для пробных ответов перед исследованием. Один браузер продолжает старую сессию по cookie. Для нового тестового участника используйте отдельный профиль/приватное окно. После окончания сессии основной опрос не предлагает начать заново.

Команда `npm start` работает до `Ctrl+C` и не публикует ссылку. Для опроса по публичной ссылке используйте `npm run survey:share`; остановка также через `Ctrl+C`.

## Где результаты

Основной файл — `data/survey.sqlite`. Страница `http://127.0.0.1:8786` показывает текущую сводку и скачивает UTF-8 CSV. После остановки сервера:

```sh
npm run export
```

CSV появится в `data/results.csv`. Его можно импортировать в Google Sheets через «Файл → Импорт». Разделитель — запятая. Экспорт не требует Google-аккаунта, токенов или доступа к Google API. Автоматической синхронизации с Google Sheets в этой версии нет.

Запись делается транзакциями SQLite. Включены WAL, busy timeout и synchronous=FULL. Пока сервер работает, не копируйте один `survey.sqlite` без его WAL: используйте CSV или SQLite Backup API. После штатного завершения можно скопировать папку `data` целиком. В неё также попадают данные о последней временной ссылке.

Одна строка CSV соответствует одному назначенному заданию, а не одному участнику. Включены и незавершённые сессии:

- `participant_id` — случайный код; имена, email, IP и полный User-Agent приложение не записывает. Cloudflare/хостинг могут вести свои технические журналы.
- `shape`, `target_label`, `media_id`, `option_order` — фигура, конкретный ролик и порядок ответов.
- `selected_label`, `correct`, `skipped` — выбранная фигура, правильность, «не могу различить».
- `clarity` — `clear`, `partly`, `unclear`; пропуск ответа не подменяет субъективную оценку.
- `active_ms_client` — время с первого показанного кадра до ответа, пока вкладка видима; включает остановки и размышление.
- `elapsed_ms_client` — календарное время с первого запуска до ответа, включая уход со страницы.
- `viewing_ms_client`, `replays`, `media_error` — время воспроизведения, повторные запуски и ошибка загрузки.
- `issued_at`, `played_at`, `answered_at`, `rated_at` — серверные отметки UTC.
- `final_instructions`, `final_comfort`, `comment`, `completed_at` — итоговая анкета; значения повторяются во всех строках участника.
- `status`: `assigned`, `opened`, `viewed`, `answered`, `rated`.

При анализе правильности берите строки с `answered_at`, а понятности — с `rated_at`. Отдельно показывайте пропуски, ошибки видео и незавершённые прохождения. Времена измеряет браузер; это исследовательские метрики, не защищённые сигналы антибота. После закрытия вкладки часть ещё не отправленных временных данных может потеряться.

## Как устроен эксперимент

Все показанные задания входят в результаты. Фигуры назначаются с приоритетом тех, которые реже назначались предыдущим участникам; порядок заданий, варианты ответа и два ролика одной фигуры перемешиваются. Это балансировка назначений, а не гарантия одинакового числа завершённых ответов. При 60 полных прохождениях получится 360 ответов, по 15 на фигуру и по 7–8 на вариант ролика при старте с пустой базы. Выборка мала для сильных выводов по отдельным устройствам.

Основной ответ фиксируется с первой попытки. Участник не видит правильность до оценки понятности и не может перебирать ответы. Повторная отправка запроса при потере сети не создаёт новую строку и не меняет уже принятый ответ. Перезагрузка страницы восстанавливает этап с сервера. «Не могу различить» и техническая ошибка сохраняются отдельно. Приложение ограничено 200 начатыми сессиями по умолчанию; очистка cookie создаёт нового участника, поэтому это не контроль уникальности людей.

Это **UX-прототип**, не CAPTCHA для защиты продакшена и не точное воспроизведение MVCAP. Ролики и набор фигур повторно используются. Устойчивость к CV/LLM не измерялась. В источнике L1 основан на тексте; здесь исследуется адаптация к силуэтам.

## Новые метрики ответа (версия 2)

CSV сохраняет прежние столбцы и добавляет:

- `response_ms_client` — основной показатель: активное время от первого показанного кадра до нажатия ответа; скрытая вкладка исключается, паузы и размышление включаются. Если видео не запускали, значение пустое, а не ноль.
- `task_ms_client` — всё время с открытия задания до ответа, включая чтение, ожидание и уход со вкладки.
- `time_to_play_ms_client` — сколько прошло от открытия задания до первого нажатия воспроизведения.
- `first_frame_delay_ms_client` — задержка от нажатия воспроизведения до первого кадра.
- `video_load_ms_client` — время от подготовки видео до первого события canplay. Это готовность к началу просмотра, не полная загрузка файла.
- `hidden_ms_client`, `tab_hides` — измеренное время и число уходов со вкладки после первого кадра; не учитывают время, когда страница полностью закрыта.
- `manual_pauses`, `replays`, `page_restores` — ручные паузы, дополнительные запуски ролика и восстановления незавершённого задания из sessionStorage. Возобновление после паузы не считается новым повтором.
- `buffering_ms_client`, `buffering_events` — ожидания данных во время воспроизведения в видимой вкладке.
- `answer_input` — mouse/touch/pen/keyboard/unknown. Координаты и траектории указателя не записываются.
- `answer_viewport_width`, `answer_viewport_height`, `video_display_width` — размер окна и отображаемого видео при ответе.
- `timing_source` — video-frame при использовании requestVideoFrameCallback; playing в браузере без этой возможности; legacy-playing для восстановленного старого замера; not-played, если видео не запускали.
- `metrics_version`, `timing_capped` — версия измерений и достижение ограничителя таймера. Активное время и просмотр ограничены одним часом; календарное время — сутками. **Это предел записи метрики, не таймер выключения сервера.**
- `task_elapsed_ms_server`, `study_duration_ms_server` — длительность задания и завершённого прохождения по серверным UTC-отметкам; включают сетевые задержки и паузы.

`elapsed_ms_client` сохраняет календарное время от первого кадра до ответа, включая закрытие/перезагрузку. `viewing_ms_client` — время воспроизведения в видимой вкладке. Запросы сохранения и сетевые повторы не увеличивают зафиксированное время ответа.

На странице результатов показаны медиана, P90, число пригодных замеров и отдельная медиана верных ответов по каждой фигуре. P90 вычисляется линейной интерполяцией между соседними значениями. Пропуски, ошибки видео, старые замеры без новых полей, legacy-playing и ограниченные таймером значения исключены из этих агрегатов, но остаются в CSV. Учитывайте число замеров: при малой выборке особенно P90 нестабилен.

Существующая база мигрирует автоматически без удаления ответов. Новые поля у старых записей остаются пустыми. Для сравнения нового эксперимента фильтруйте `metrics_version=2`; отдельно анализируйте устройства, пропуски и восстановленные страницы. Это время решения задачи, а не лабораторный замер чистой моторной реакции. Метрики поступают от браузера и не являются защитой от автоматизации.

## Анимации

480×280, 3 секунды, 30 FPS, MP4/H.264. Цвет фона `#35204f`, точек `#f9bd77`. Внутри маски текстура движется вправо, снаружи — влево. Маски и правильные ответы не выдаются публичным API. Начало видео не содержит контура; сжатие и последующие кадры требуют отдельной проверки при исследовании устойчивости.

При изменении фигур можно заново сгенерировать медиа. Нужны Python, Pillow и FFmpeg:

```sh
python3 -m venv .venv
.venv/bin/pip install 'Pillow>=11,<13'
.venv/bin/python tools/generate_media.py
```

Добавлены 12 простых фигур: круг, квадрат, треугольник, звезда, полумесяц, облако, сердце, чашка, ключ, морковь, парусник и самолёт. Всего 24 фигуры, по два ролика с разной текстурой точек. Обзор всех силуэтов — `tools/shape-contact-sheet.png`.

Новая версия исследования — `l1-v2-24-shapes`, она записывается в столбец CSV `study_version`. Ранее начатые прохождения сохраняют прежние задания, ответы и версию `l1-v1`; новый набор доступен новым участникам. Балансировка учитывает все прошлые назначения, поэтому после расширения новые фигуры получают приоритет. При анализе сравнивайте версии отдельно: набор отвлекающих вариантов расширился.

Генератор пропускает существующие ролики. При добавлении фигур сохраняйте старые идентификаторы и файлы, меняйте `STUDY_VERSION`. При изменении уже существующих масок или параметров нужна новая версия идентификатора медиа и отдельный эксперимент: назначенные участникам ролики нельзя подменять.

## Бесплатный тест на Railway — пошагово

У новых аккаунтов Railway есть Trial: $5 кредита на срок до 30 дней; после него — Free с $1 кредита в месяц. Free/Trial поддерживает том 0,5 ГБ. Для небольшого суточного опроса это подходящий вариант, но доступность определяется оставшимся кредитом и ограничениями аккаунта. Не подключайте Hobby/Pro для этого теста. У Limited Trial есть сетевые ограничения; при необходимости попробуйте верификацию GitHub. Если Railway требует платный тариф для продолжения, не оплачивайте автоматически: сначала проверьте статус аккаунта.

Условия проверены 12 октября 2026: [Trial](https://docs.railway.com/pricing/free-trial), [лимиты Free/Trial](https://docs.railway.com/pricing/plans), [постоянные тома](https://docs.railway.com/volumes).

### 1. Регистрация и вход

Откройте [railway.com/login](https://railway.com/login), зарегистрируйтесь. В терминале Mac установите Railway CLI и войдите:

```sh
brew install railway
railway login
```

Вход завершится в браузере. Пароль в файлы проекта записывать не нужно. Способ установки подтверждён [документацией Railway CLI](https://docs.railway.com/cli).

### 2. Откройте папку проекта в терминале

Если папка лежит на рабочем столе:

```sh
cd ~/Desktop/l1-survey
```

В этой папке должны находиться `Dockerfile`, `package.json`, `server.mjs`, `media/`. Не загружайте всю рабочую папку Codex. Локальные ответы, CSV, `.env` и служебные файлы исключены из загрузки через `.railwayignore`.

### 3. Создайте сервис и постоянный диск

Выполняйте по одной команде. Этот блок нужен только при первом создании проекта:

```sh
railway init --name autumn-l1-survey
railway add --service survey
railway variable set HOST=0.0.0.0 PORT=8785 DATA_DIR=/app/data RAILWAY_RUN_UID=0
railway volume add --mount-path /app/data
```

Если CLI предлагает выбрать сервис, выбирайте `survey`. Проект и сервис после создания связываются с текущей папкой. Проверьте в панели Railway, что volume подключён именно к `survey`, путь — `/app/data`, размер не превышает доступные 0,5 ГБ. Не создавайте отдельную PostgreSQL-базу: используется SQLite в томе.

`RAILWAY_RUN_UID=0` нужен для записи в том Railway, который монтируется владельцем root; это [настройка из официальной документации](https://docs.railway.com/volumes#permissions). Публичным будет только порт 8785. Порт результатов 8786 остаётся локальным внутри контейнера.

### 4. Загрузите код и получите ссылку

```sh
railway up --ci
railway domain --port 8785
```

Дождитесь успешного деплоя. Railway соберёт приложенный Dockerfile с Node.js 24. Локальный Docker для этого не нужен; GitHub-репозиторий тоже не обязателен. CLI выведет HTTPS-ссылку вида `https://….up.railway.app`. Именно её отправляйте участникам. HTTPS-сертификат выдаётся автоматически. [Загрузка локального кода](https://docs.railway.com/cli/up), [домен](https://docs.railway.com/cli/domain).

В настройках сервиса оставьте одну реплику. Для суточного теста отключите Serverless/App Sleeping, если этот режим включён; автоматического таймера остановки в приложении нет. В настройках Healthcheck можно указать `/health`.

После публикации Mac и локальный терминал можно выключить. Перед рассылкой откройте публичную ссылку в приватном окне, проверьте открытие первого задания и запись одного ответа. Для чистой выборки удобнее провести этот пилот в отдельном проекте, а затем создать новый проект для основного исследования. Не удаляйте накопленные результаты из действующего исследования.

### 5. Скачайте CSV с хостинга

Всё ещё из связанной папки проекта:

```sh
railway ssh -- node scripts/export.mjs
mkdir -p exports
railway volume files download /results.csv ./exports/results.csv
```

Первая команда создаёт свежий CSV в `/app/data/results.csv` внутри контейнера; вторая скачивает его на Mac. Пути `railway volume files` считаются от корня тома, поэтому используется `/results.csv`. Если CLI попросит выбрать том, выбирайте том сервиса `survey`. При первом SSH-подключении CLI может предложить зарегистрировать SSH-ключ — следуйте его диалогу. [SSH](https://docs.railway.com/cli/ssh), [скачивание из тома](https://docs.railway.com/cli/volume).

Для повторной выгрузки укажите новое локальное имя, например `./exports/results-final.csv`. Откройте CSV в Google Sheets: «Файл → Импорт», разделитель — запятая. Экспорт можно делать и во время работы опроса. Не скачивайте один `survey.sqlite` из работающего приложения без WAL; для анализа используйте CSV.

Страница результатов на `127.0.0.1:8786` в вашем Mac показывает **локальную** базу, а не Railway. Для просмотра облачной сводки можно использовать SSH forwarding по [официальной инструкции Railway](https://docs.railway.com/cli/ssh#forward-a-port-with-ssh--l), пробросив удалённый `127.0.0.1:8786` на свободный локальный порт.

### 6. Завершите опрос вручную

Когда участники закончат, сначала скачайте итоговый CSV. Затем:

```sh
railway down
```

Команда убирает текущий деплой. Закрытие терминала или `Ctrl+C` в логах Railway **не выключает** облачный сервер. Том с данными — отдельный ресурс; он расходует квоту хранения, пока существует. После проверки сохранённого CSV можно удалить тестовый проект в панели Railway. Это удалит и облачную базу, поэтому делайте это только после выгрузки. Автоматической остановки через сутки нет.

Текущий проект подключён к [GitHub](https://github.com/naritai/autumn-l1-survey), ветка `main`. После обновления файлов проверьте появление нового деплоя в Railway. Если автодеплой не запустился, из связанной папки проекта выполните `railway redeploy --from-source --service survey --environment production --yes`: эта команда берёт последний коммит из GitHub. Ссылка опроса: https://survey-production-7f02.up.railway.app. Не повторяйте `railway init` и создание тома. Загрузка через GitHub используется вместо `railway up --ci`, который здесь завершался тайм-аутом при создании снимка кода. Для обновления набора фигур соблюдайте сохранение старых медиа и версий исследования, описанное выше.

## Другой хостинг

Проект переносим на сервер с Node.js 24 и постоянным диском. Запуск: `HOST=0.0.0.0 DATA_DIR=/persistent/path npm start`. Внешний HTTPS обеспечивает reverse proxy/хостинг. Админский порт остаётся на loopback; сводку можно открыть через SSH forwarding, экспорт выполнить командой.

```sh
docker build -t autumn-l1-survey .
docker run --rm -p 8785:8785 -v autumn-survey-data:/app/data autumn-l1-survey
```

Для SQLite нужен один экземпляр приложения и локальный постоянный диск. Обычный статический хостинг для этой версии не подходит. Бесплатные сервисы с временным диском могут удалить базу при перезапуске; например, [Render документирует это ограничение](https://render.com/docs/free). Для короткого сеанса проще локальный запуск через туннель.

## Проверки

```sh
npm test
```

15 тестов проверяют полный путь прохождения, серверную проверку ответа, повторную отправку без дубликатов, изоляцию участников, восстановление после открытия базы, расширение каталога без потери назначений и ответов, миграцию старых данных, первый кадр/паузы/скрытие вкладки/повторы, медиану/P90, CSV и доступ к результатам. Тестовые базы создаются во временных директориях и удаляются.

Структура: `server.mjs` — HTTP и маршруты; `lib/store.mjs` — SQLite; `public/` — страницы участника/исследователя; `media/` — ролики; `catalog.json` — закрытый каталог; `scripts/` — запуск туннеля, установка туннеля и CSV.
